This document maps the analog circuit blocks identified in
[`CIRCUIT_RESEARCH.md`](./CIRCUIT_RESEARCH.md) onto concrete C++ /
JUCE modules. Each section pins one *circuit* block to one *DSP*
class, names the algorithm, and lists the unit tests that will prove
the model is faithful.

## Targets in priority order

1. **TriangleCoreVCO** — replace `DriftedVCO` with a real ICL8038-style
   triangle-core oscillator + piecewise-linear sine shaper.
2. **PiezoTrigger** — peak-detector + Schmitt-trigger module so the
   plugin can accept real piezo audio on a side-chain input as well as
   the existing pad clicks.
3. **TwinEnvelope** — promote the current `ExpEnvelope` to a
   first-class twin (amp + pitch) generator with identical RC topology
   driven from the same trigger but with independent R/C values.
4. **OTAVCA** — model the VCA non-linearity that an OTA pair (CA3080 /
   LM13700) produces.
5. **NoiseBPState** — replace the IIR band-pass + peaking pair with a
   TPT state-variable filter that exactly matches the analog one-pole
   pair the noise generator on the original PCB uses.
6. **LFOSchmitt** — relaxation-oscillator LFO (op-amp Schmitt +
   integrator) producing triangle / sine.
7. **MultiVCOPullRouter** — the cascade-trigger feature.

Each module lives in `Source/DSP/` (a new subdirectory) and is
exercised by a Catch2 unit test in `tests/` (added in Phase 2.5).

## 1. TriangleCoreVCO — modelling the ICL8038

### Reference circuit (block-level)

A current-controlled triangle-core, exactly as the ICL8038 implements
it:

```
            i_up     i_dn
              ▲       ▼
        ┌──── + ──────┐
        │             │             VOUT_tri  ──►  shaper  ──►  VOUT_sin
   ──►──┤    Ct   ────┼──►  comp(V_thr_hi)  ──► VOUT_sqr
        │             │           │
        └─────────────┘           ▼
                              SR flip-flop
                                  │
                          gates i_up vs i_dn
```

Frequency is `f = i / (2 · C · V_swing)` so the relationship between
control input and frequency is **linear**, not exponential. We expose
the control input as a frequency in Hz; OCTAVE / TUNING / BEAT TUNE
sliders are converted to a frequency multiplier upstream the same way
the analog 5-step resistor ladder does.

### Algorithm — TPT triangle core (zero-delay feedback)

```
state.phase   ∈ [-1, +1]      // capacitor voltage, normalised
state.rising  ∈ {true, false}

for each sample:
    dt = freq / sr
    if state.rising:
        state.phase += 2·dt
        if state.phase ≥ +1:
            state.rising = false
            // PolyBLAMP correction at the slope discontinuity:
            // see Välimäki, "Antialiasing oscillator soft sync",
            // DAFx-16, eq. 7.
            apply_polyBLAMP(state.phase - 1)
    else:
        state.phase -= 2·dt
        if state.phase ≤ -1:
            state.rising = true
            apply_polyBLAMP(state.phase + 1)

    tri = state.phase
    sqr = state.rising ? +1 : -1   // also gets a PolyBLEP per side
    sin = sineShaper(tri)
```

* `PolyBLAMP` (Polynomial Band-Limited rAMP) is the correct
  anti-aliasing pre-corrector for a triangle's *slope* discontinuity
  (where PolyBLEP is for the *value* discontinuity of square/saw).
  This is what makes a triangle-core sound non-aliased at any
  frequency.

### `sineShaper(tri)` — piecewise-linear breakpoint approximation

The ICL8038 sine output is generated by a **7-breakpoint diode
network** (each breakpoint contributes a different slope). We
approximate the same THD signature (1 % total, odd-only harmonics)
with a 5th-order Lagrange:

```cpp
float sineShaper(float tri)  // tri in [-1, +1]
{
    // Bhaskara-style polynomial that matches ICL8038 THD signature.
    // f(x) ≈ sin(π/2 · x) with ~1 % THD, odd harmonics only.
    const float x = tri;
    const float ax = std::abs(x);
    const float y = x * (1.5f - 0.5f * ax * ax);  // 3rd order
    // small 5th-order correction for the inflection point
    return y + (x - y) * 0.176f;
}
```

The exact coefficients will be fit against the ICL8038 sine output
reference curve (Intersil datasheet figure 5) by least-squares once we
have unit tests in place.

### Selectable output

The DS-4 panel switch picks one of {sine, triangle, square, saw}.
Sine, triangle, square come *for free* from the same triangle core
(simultaneously, exactly like the 8038). Saw is *not* a Syndrum
output; we add it as a useful modern extension by integrating the
square (with leak compensation), as our current `DriftedVCO::triangle`
already does the dual.

### Analog drift retained

The three drift layers from the current `DriftedVCO`
(per-hit ±3 cents, slow random walk, continuous wobble) are retained.
On a real ICL8038 these come from temperature on the current sources
and on the timing capacitor's leakage — the same statistical
behaviour, just modelled phenomenologically.

## 2. PiezoTrigger — front-end peak detector

The original is a transistor peak detector (envelope follower) feeding
a CD4093 Schmitt-trigger inverter. The Schmitt's hysteresis is what
prevents the pad from re-triggering during the ringing tail.

### DSP equivalent

```
peak = max(peak·a, |x|)         // a = exp(-1/(τ·sr)), τ ≈ 5 ms
hold = max(hold,   peak)        // hold for ≥ pulse-width samples
if  hold > V_hi and not armed:  armed = true;  emit trigger(velocity = hold)
if  hold < V_lo and     armed:  armed = false
```

Velocity is the peak value at trigger time, mapped through the
`SENSE LEVEL` pot (linear pot × peak detector output).

This lets the plug-in be driven by a real piezo on an audio input bus,
not just by the GUI pad. Logic Pro users can wire a guitar/contact
piezo into the AU's side-chain.

## 3. TwinEnvelope

The Pollard schematic shows **one trigger, two RC envelopes**:

```
                R_a │
   trigger ─────┐  │  ┌──── amp env out (to VCA)
                ▼  ▼  │
                 C_a ─┤
                R_s   │
                ─/\/\─┴─ ground
```

A separate `R_p / C_p` pair generates the pitch sweep envelope.

* **Charge phase** (during trigger pulse): C charges through
  R_a (= ATTACK pot).
* **Discharge phase** (after pulse ends): C discharges through R_s
  (= SUSTAIN pot).

The voltage tracks `V_target + (V_start - V_target) · exp(-t / τ)`
with `τ = R · C`. Our current `ExpEnvelope` does the discharge
correctly. Phase 2 adds:

* The voltage being charged *to* depends on whether `BEAT SENSE` is
  ON. If ON, the peak voltage tracks the trigger-time peak from
  PiezoTrigger; if OFF, it's a fixed +V_cc.
* The pitch envelope's start voltage is also peak-tracked when
  `BEAT SENSE` is ON.

## 4. OTAVCA — modelled non-linearity

A CA3080 / LM13700 OTA in current-control mode behaves like:

```
i_out = I_abc · tanh(V_in / (2·V_T))
```

where `V_T ≈ 26 mV` is the thermal voltage. The two characteristic
features are:

* Soft saturation as input level approaches ±60 mV.
* Output proportional to the *control current* `I_abc`, which we
  drive from the amp envelope.

DSP equivalent (one sample):

```cpp
float OTAVCA::processSample (float in, float ctrl)
{
    constexpr float Vt2 = 0.052f;      // 2 · 26 mV
    const float gain    = ctrl;        // 0..1, from amp env
    return gain * std::tanh (in / Vt2) * Vt2;
}
```

This replaces the plain gain + tanh hack in the current `Voice.cpp`.
It also explains where the DS-4's characteristic *bloom* at high
output settings comes from — at saturation the OTA produces a smooth
third-harmonic distortion, not the abrupt clip you'd get from an
op-amp limiter.

## 5. NoiseBPState — TPT state-variable filter

A 2nd-order analog band-pass with controllable centre + Q is normally
implemented in DSP as a biquad. For self-modulating filters
(SWEEP_DIR animating the centre at audio rate), the topology-preserving
transform avoids the cutoff-vs-Q coupling artefact biquads produce
near Nyquist:

```
g  = tan(π · f0 / sr)
k  = 1 / Q
v1' = (v1 - g · k · v1 - g · v2 + x) / (1 + g·k + g²)
hp  = (x - k · v1' - v2 - g · v1') / (1 + g·k + g²)   // unused
bp  = g · hp + v1
lp  = g · bp + v2
v1  = 2 · v1' - v1
v2  = 2 · lp  - v2
return bp
```

`v1`, `v2` are the two integrator states.  The +6 dB peaking
emphasis is now a separate one-pole peaking filter cascaded on the
band-pass.  This replaces the `juce::dsp::IIR` chain in
`NoiseVoice.cpp` and removes the heap allocation that the coefficient
rebuild currently does every 32 samples.

## 6. LFOSchmitt — relaxation oscillator

The Pollard manual mentions no LFO, but the DS-4 adds one per channel
and the panel offers FREQUENCY + LEVEL + ON/OFF. The cheap-and-good
analog LFO of 1978 was the op-amp Schmitt + RC integrator pair:

```
            R         C
   ──/\/\─┬──╫├──── V_out (triangle)
          │
          ●─────┐
                ▼
            Schmitt (op-amp + 2 resistors)
                │
   V_sqr ◄──────┘
```

When `V_sqr` flips, the integrator's input flips sign and the triangle
starts ramping the other way. We get triangle and square from the
same loop. The DS-4 panel symbol is "∿" so it's the triangle output
that reaches the VCO CV.

DSP: it's a single ZDF integrator + a Schmitt comparator. ~10 lines.
The current `lfoPhase += rate/sr; sin(2π·phase)` in `Voice.cpp` is
the cheap version; this replaces it.

## 7. MultiVCOPullRouter

When `MULTI VCO` is pulled on Ch N, that channel's trigger pulse is
*also* injected into Ch (N+1)'s VCO CV pin as a fixed offset current,
*without* gating its envelope (the other channel's amp env stays
silent). The audible effect is that triggering Ch1 fires Ch1's amp
envelope but momentarily shifts Ch4's pitch.

This is more interesting than the simple "play a unison voice" our
current model does. To match it:

* `Voice::trigger()` should *also* call `state.channels[next]
  .pitchEnv.kickWithoutAmp()`.
* The neighbour's pitch envelope contributes to its VCO frequency
  through the existing sweep CV summing point.

Implementation is a few lines in `PluginProcessor::processBlock` —
when handling a trigger, also peek at the *next* channel's
`pMultiVCO` flag and, if set, inject a pitch-only retrigger.

## Validation plan

Once Phase 2 lands, we validate against the real instrument as
follows:

* If we get hold of a DS-4M (or the Eurorack DS-1), record A/B clips
  with a known set of front-panel positions for all four channels.
* Run the plug-in with the same parameter values and capture its
  output to a WAV.
* Compare *envelope shape*, *spectral content*, and *first-formant
  centre frequency* across the recordings. Tune the
  `TriangleCoreVCO::sineShaper` coefficients and the
  `NoiseBPState` Q values until the magnitude spectra match within
  ±2 dB across the 0–10 kHz band on identical pad inputs.
* Open question: at what point do we stop fitting? Probably when the
  audible difference between plug-in and instrument falls below the
  natural hit-to-hit variability of the analog itself (the random
  drift we model in §1 is *also* present in the real circuit).
